# ADR-002 — System of record and sync path

> Generated by Project Launcher Pro v4.4.1 on 7/29/2026

## Context

Reports must be historical and filterable. UI must not pull full Frotcom history on each page load. Daily import of previous calendar day is required.

## Alternatives

### A — Supabase SoR + n8n daily Frotcom import; UI reads DB — 90/100

Clear separation; idempotent upsert; backfill possible; matches Anweisungen architecture principle.

- Cost: 2/5
- Speed: 4/5
- Maintainability: 5/5
- Scalability: 3/5
- Risk: 2/5
- Lock-in: 3/5

### B — Dashboard calls Frotcom live per request and caches briefly — 40/100

Violates architecture principle; weak historical integrity; rate-limit fragile.

- Cost: 2/5
- Speed: 3/5
- Maintainability: 2/5
- Scalability: 2/5
- Risk: 5/5
- Lock-in: 4/5

### C — Batch files drop (CSV/SFTP) into storage then ETL — 55/100

Works without API but loses near-daily automation quality and richer Frotcom fields unless files are rich.

- Cost: 3/5
- Speed: 2/5
- Maintainability: 3/5
- Scalability: 2/5
- Risk: 3/5
- Lock-in: 2/5

## Decision

Supabase as system of record; n8n orchestrates daily Frotcom pull/normalize/upsert; dashboard reads Supabase only for history.

## Rationale

Directly implements Anweisungen §4; enables sync_runs audit and idempotent vehicle_daily_reports.
