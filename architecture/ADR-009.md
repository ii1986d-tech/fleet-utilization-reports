# ADR-009 — PDF transport-order extraction via multimodal AI APIs

> Status: **ACCEPTED (design binding)** — 2026-08-04  
> Accepted by: **I. Dimitrov**  
> Pack: PACK-006  
> Architect Re-Review: **ARCHITECT_REVIEW_PASS**  
> DS-004: **COMPLETE** (26 PDF + 26 manifests locally; 8 human_verified)  
> DS-005: **OPEN** (blocks live-provider / real-customer processing)  
> Apply: **not authorized** — separate human Apply approval required  
> Evidence: `sprints/sprint-006/ARCHITECT-REVIEW.md` · `BUILDER-DRY-RUN.md` · `DRY-RUN-READINESS.md`  
> Private samples: `references/private/pack-006/` (gitignored) — never commit binaries/manifest values

## Context

MVP v1.0.0 is complete. PACK-006 extracts structured transport-order data from PDFs via **external multimodal AI APIs**, then requires **field-level human review and confirmation** before any operational use or next workflow step.

Domain shape:

- private original PDF storage  
- immutable extraction snapshot  
- editable working transport order with **aggregate versioning**  
- ordered pickup/delivery stops with **stable `stop_id`**  
- first-class **partial-load positions** and **transport legs**  
- field-level provenance + **persisted review states**  
- transactional confirmation + idempotent upload/extract/completion  

Binding business rule: **AI extraction results are suggestions only.**

## Decision

### 1. Domain isolation (unchanged)

Separate transport-order domain from Excel assignment import. Do not extend `vehicle_assignments.source` for PDF in PACK-006.

### 2. Provider strategy (binding)

| Role | Provider |
|---|---|
| **Primary** | **Gemini API** |
| **Optional** | **Grok / xAI API** (fallback / second opinion only) |

No default dual-provider calls. APIs not assumed free. Real customer PDFs require DS-005. Free-tier/dev limited to anonymized/synthetic samples.

### 3. Provider-independent interface

`PdfExtractionProvider`: `extractPdf`, `providerName`, `modelName`, `supportsNativePdf`, `supportsStructuredOutput`, `uploadDocument`, `deleteRemoteDocument`, `healthCheck`, `normalizeProviderError`.

Adapters (Apply later): `GeminiPdfExtractionProvider`, `XaiPdfExtractionProvider`. Domain uses internal schema only.

### 4. Server-side security (binding)

Server-only: `GEMINI_API_KEY`, `XAI_API_KEY`. Forbidden: `NEXT_PUBLIC_*` AI keys, browser→provider calls, credentials in Git/DB/logs. Browser uploads only to the app server.

### 5. AI extraction data flow

1. Authenticated upload (admin or manager) with **idempotency key**  
2. Validate extension / MIME / PDF magic bytes / size / pages / safety; sanitize filename; generate storage key  
3. Private Storage (no public bucket)  
4. Extraction run (idempotent; auditable attempts)  
5. Provider (default Gemini) under timeout + bounded retry  
6–8. Structured response → **strict** internal schema validate  
9. Immutable extraction snapshot  
10. Working order + stops (`stop_id` UUIDs) + optional partial loads / legs; every review target `review_status = pending_review` (or `conflict` / `extraction_failed`)  
11. Human Save → edit/confirm with **aggregate CAS**  
12. **Weiter** only after catalog + structural minimum + `expected_version` (server TX)  
13. Remote provider file delete/expire + status  
14. Only then may PACK-007 consume the order  

AI must never overwrite a confirmed field or confirmed order without explicit re-confirmation after edit.

### 6. Structured extraction schema (internal)

Minimum: document metadata; tour/Bordero/refs/Frachtbrief; clerk; remarks; freight `{amount,currency}`; paid/empty km; plates; cargo measures; ordered stops (`pickup|delivery|other`) with address components, dates, confidence, source page/snippet; **partial_load_positions**; **transport_legs**. Multi-stops not collapsed. Repeated physical addresses remain separate stop entities. Shared delivery stops supported via associations by `stop_id`.

### 7. Roles for review and confirmation (binding — resolves OQ-006-01)

Existing Auth roles only (`app_metadata.role`):

| Role | Upload/extract | Edit / Save / Reorder | Confirm fields | Progress **Weiter** | Read |
|---|---|---|---|---|---|
| `admin` | yes | yes | yes | yes (when complete) | yes |
| `manager` | yes (acting as dispatcher) | yes | yes | yes (when complete) | yes |
| `viewer` | no | no | no | no | yes |

- **Do not** introduce a generic `dispatcher` Auth role without a separate architecture decision.  
- “Dispatcher” in UX copy means **manager (or admin) performing dispatch work**, not a new role claim.  
- Excel assignment import remains admin-only; do not widen `import_jobs` RLS.

### 8. Field-level review states (binding — DB source of truth)

Every extracted / working review target persists `review_status` ∈:

| State | Meaning |
|---|---|
| `pending_review` | AI value present; no human confirmation |
| `edited_pending_review` | Human changed value; not yet confirmed |
| `confirmed` | Authorized user explicitly confirmed current value |
| `missing_confirmed` | Authorized user confirmed value absent in document |
| `not_applicable` | Authorized user confirmed field irrelevant for this order |
| `conflict` | Contradictory values; human resolution required |
| `extraction_failed` | Provider could not extract a reliable value |

UI color is **not** source of truth. Persist state in DB. Labels/icons required in addition to color.

**Terminal (resolved) states:** `confirmed` | `missing_confirmed` | `not_applicable`  
**Non-terminal (blocking) states:** `pending_review` | `edited_pending_review` | `conflict` | `extraction_failed`

### 9. Field provenance (binding)

Per review target (working layer), retain at minimum:

Stable identity: `entity_type` + `entity_id` + `field_name` (not array-index paths).  
Also: `extracted_value`, `current_value`, `extraction_confidence`, `source_page`, optional controlled `source_snippet` (never full PDF body), `provider`, `model`, `extraction_run_id`, `review_status`, `edited_by`, `edited_at`, `confirmed_by`, `confirmed_at`, optional confirmation note.

Display paths like `stops[0].city` may appear in UI only; they are **not** persisted identity.

Immutable extraction snapshot **never** overwritten. Working order holds editable `current_value`.

### 10. Confirmation behavior (binding)

Authorized users may: confirm unchanged; edit then confirm; mark optional missing as `missing_confirmed`; mark `not_applicable` where allowed; view original AI value, confidence, source page/snippet.

**Never** auto-confirm because of: high confidence, page open, edit alone, another field confirmed, or valid JSON from AI.

Confirmation and related audit events persist **transactionally**. Partial confirmation persistence is forbidden. Duplicate confirmation submits are safe (idempotent; no conflicting state).

### 11. Edit after confirmation (binding)

If a `confirmed` (or `missing_confirmed` / `not_applicable`) field’s value/decision changes:

1. Immediately clear confirmed state → `edited_pending_review` (or appropriate non-confirmed state)  
2. Clear/supersede `confirmed_by` / `confirmed_at` per audit model  
3. Require new explicit confirmation  
4. Block **Weiter** again if field is mandatory  

Retain full audit history (old/new value, user, timestamps, prior and new confirmation).

### 12. Workflow gate — **Weiter** (binding; closes OQ-006-11)

**Weiter** disabled in UI until review-resolution and structural minimum are satisfied.

#### 12.1 Review-resolution requirement

Every canonical review target shown for the order must have a **terminal** human decision (`confirmed` | `missing_confirmed` | `not_applicable`).

Applies to: order identifiers; references; remarks; responsible clerk; consignment-note fields; vehicle and trailer fields; freight and currency; paid and empty kilometers; cargo totals; every stop’s type, sequence, address and time fields; every partial-load association; every transport-leg association; **stop-order confirmation**.

Optional values need not be non-null, but must be explicitly resolved as `confirmed`, `missing_confirmed`, or `not_applicable`.

Must **not** proceed when any review target is `pending_review`, `edited_pending_review`, `conflict`, or `extraction_failed`.

#### 12.2 Structural minimum

Weiter also requires at least:

- one persisted working order  
- one human-confirmed business identifier  
- ≥1 pickup stop and ≥1 delivery stop  
- unique sequential stop ordering (`sequence` unique per order after TX)  
- every stop has stable `stop_id` and confirmed type  
- every stop has confirmed structured location **or** confirmed original/raw address text  
- all partial-load and leg references point to valid `stop_id`s  
- stop order explicitly confirmed  
- no unresolved conflict; no `extraction_failed`  
- request `expected_version` matches aggregate `version`  

#### 12.3 Server enforcement

Server **revalidates in one transaction**: `expected_version`, persisted review states, structural invariants, completion status. Frontend disable is UX only.

On incomplete review: **HTTP 409** · `code: ORDER_REVIEW_INCOMPLETE` · body lists unresolved **stable** targets (entity_type/entity_id/field_name) without sensitive PDF content in logs.

On version mismatch: **HTTP 409** · `code: ORDER_VERSION_CONFLICT` · client must reload before retry.

Stale clients cannot complete review merely because an older UI shows all fields as confirmed.

### 13. Stops / multiple addresses (binding)

Each stop reviewed separately (type, sequence, company, street, house number, postal code, city, country, date, time window, references, remarks, …).

- Manually added stop starts as `edited_pending_review` (all its fields as applicable).  
- Confirming one stop/address does **not** confirm the array.  
- Incomplete addresses: extract only values present on the PDF; do not invent streets.

### 13a. Manual stop reordering + stable stop identity (binding — PACK-006)

Every operational stop has:

| Field | Rule |
|---|---|
| `stop_id` | Immutable UUID |
| `order_id` | Immutable parent reference |
| `sequence` | Mutable positive integer; unique within order after TX |
| `type` | `pickup` \| `delivery` \| `other` |
| address + review fields | Per-field review states |
| aggregate version | Mutations bind to order `expected_version` |

Admin and manager may reorder working-order stops. Viewer remains read-only.

**Interaction (both required):**

- Drag-and-drop reorder in the stop list  
- Keyboard-accessible move-up / move-down controls  
- Each stop shows a visible sequence number that updates after reorder  

**Semantics after reorder:**

1. Drag/keyboard changes **`sequence` only**; `stop_id` never changes.  
2. Previous stop-order / sequence confirmations are immediately invalidated.  
3. The reordered sequence enters `edited_pending_review` until explicit confirm.  
4. Dispatcher (admin/manager) must explicitly confirm the new order.  
5. **Weiter** stays blocked until stop order is confirmed.  
6. Server revalidates sequence uniqueness + confirmation + `expected_version`.  
7. Audit `stops_reordered` retains **ordered `stop_id` arrays** (old and new) plus sequence maps.  
8. Original AI-extracted order remains unchanged in the immutable extraction snapshot.  
9. Partial-load and transport-leg FKs use `stop_id`; reorder does not invalidate entity identity.  

**Out of PACK-006:** No automatic route calculation, distance comparison, shortest-route suggestions, corridor logic, or Maps routing API. Those remain **PACK-007**.

### 13b. Partial-load positions and transport legs (binding)

#### `transport_order_partial_load_positions`

`position_id` (UUID), `order_id`, optional `position_number`, `pickup_stop_id`, `delivery_stop_id`, position-level references, optional position-level cargo (null when not documented). **No invented allocation** of aggregate cargo to positions.

#### `transport_order_legs`

`leg_id` (UUID), `order_id`, `origin_stop_id`, `destination_stop_id`, `sequence`, associated references, optional distance fields (document/human supplied only). **No automatic route calculation** in PACK-006.

Rules: shared delivery supported; repeated addresses = separate stops; roundtrips = separate stops and legs; invalid stop references rejected server-side; associations always by `stop_id`.

### 14. Group confirmation (optional UX)

“Confirm all visible fields” allowed only when: authorized; no conflicts; no required empties; explicit list of what will be confirmed; server re-checks same conditions; transactional; CAS on aggregate version. No hidden automatic bulk-confirm.

### 15. Audit events (binding — complete catalog)

Append-only events. Actions include at least:

`upload_created`, `upload_rejected`, `extraction_started`, `extraction_completed`, `extraction_failed`, `extraction_retry_requested`, `field_edited`, `field_confirmed`, `missing_confirmed`, `not_applicable_confirmed`, `confirmation_revoked_by_edit`, `conflict_recorded`, `conflict_resolved`, `stops_reordered`, `stop_order_confirmed`, `review_completed`, `completion_gate_rejected`, `stale_write_rejected`, `idempotency_conflict`

Where applicable each event records: actor, timestamp, `order_id`, aggregate version before/after, `entity_type`, `entity_id`, old/new value or sequence (`stop_id` arrays for reorder), provider/model/schema/prompt versions, reason/error code.

**Do not** store unnecessary sensitive PDF text, credentials, or full document bodies in audit events.

### 16. UI visual language (binding intent)

| Persisted state | Visual intent | Label (DE examples) |
|---|---|---|
| `pending_review` | Neutral/light | Ungeprüft |
| low confidence / `conflict` | Amber/orange warning | Konflikt – Prüfung erforderlich |
| `edited_pending_review` | Highlighted review | Geändert – Bestätigung erforderlich |
| `confirmed` | Dark blue / blue + confirmation icon | Bestätigt |
| `missing_confirmed` / `not_applicable` | Distinct neutral confirmed | Fehlend bestätigt / Nicht zutreffend |
| `extraction_failed` | Warning | Extraktion fehlgeschlagen |

Always pair color with icon + text label + tooltip/status. Accessibility/contrast required.

### 17. No automatic trust

AI output untrusted: schema validate; reject malformed; normalize units/currencies; validate ranges/dates/arrays; flag missing/conflict/low confidence; never invent values. Human confirmation required before operational use.

### 18. Extraction-run audit / failure / cost / comparison / boundaries

Extraction-run records; bounded retries; non-silent xAI fallback only under §22; configurable cost/quota; optional anonymized comparison mode; PACK-006 excludes automatic route math / shortest-route optimization (007) and management export (008); PACK-006 includes manual stop reorder + confirmation; local OCR not primary extractor.

### 19. Extraction accuracy evidence (binding framework)

Evaluate Gemini (primary) / optional xAI against expected-field manifests using metrics in `SAMPLE-ANALYSIS.md` §5.  
**Samples on disk** under ignored `references/private/pack-006/` (8 human_verified). Live provider evaluation still requires **DS-005**. Tracked docs must not copy operational values from those manifests.

### 20. Field confirmation (reconfirmed)

Every extracted field starts `pending_review` (or `conflict` / `extraction_failed`). No field becomes operational before explicit admin/manager confirmation. Viewer cannot confirm. Server Weiter gate: 409 `ORDER_REVIEW_INCOMPLETE`.

### 21. Concurrency and aggregate versioning (binding — closes C1)

Working order aggregate (`transport_orders`) has:

- `version` — integer, monotonically increasing  
- `updated_at`  
- `updated_by`  

Every mutating request supplies `expected_version`. Writes use compare-and-swap:

`UPDATE … WHERE id = :id AND version = :expected_version`

Successful mutation increments `version` exactly once. Stale mutation → **HTTP 409** · `ORDER_VERSION_CONFLICT`. Client must reload before retry.

Weiter/completion validates in **one transaction**: `expected_version`, persisted review state, structural invariants, completion status. Partial confirmation persistence is forbidden. Review completion either succeeds completely or rolls back completely. Duplicate completion submit is safe (no duplicate domain/audit side effects beyond idempotent acknowledgment).

### 22. Idempotency (binding)

#### Upload

- Client supplies idempotency key.  
- Same key + same payload → original result.  
- Same key + different payload → reject (`IDEMPOTENCY_KEY_REUSE_MISMATCH`).  
- PDF content hash stored for duplicate detection.  
- Duplicate hash detection must **not** silently merge two intentionally distinct business orders (surface conflict / require explicit human choice; error `UPLOAD_DUPLICATE_CONTENT` or policy-defined equivalent).

#### Extraction

- Extraction request has idempotency key.  
- Retry does not create duplicate extraction records or duplicate orders.  
- Provider attempts remain auditable.  
- Retry limits explicit (default design: max **3** attempts per run including first).  
- Terminal failure persists `extraction_failed` on affected targets / run.  
- Retry after terminal failure requires **explicit user action** (`extraction_retry_requested` audit).

#### Review completion

- Repeated completion submit is safe; does not create duplicate audit or domain records.

### 23. Provider robustness (binding)

- Strict adapter + strict response-schema validation.  
- Persist `prompt_version`, `schema_version`, `provider`, `model` on extraction runs.  
- Explicit timeout (design default: **60s** provider call budget; Apply may tune under ADR).  
- Bounded retries (design default: **3** total attempts); classify retryable vs non-retryable.  
- **No silent provider fallback.**  
- Fallback to xAI requires: DS-005 approval covering that provider; explicit configured policy; audit entry.  
- Malformed provider output → controlled failure state; `extraction_failed` remains review-blocking.  
- Unapproved provider use forbidden. Live PDFs blocked while DS-005 OPEN.

### 24. File security and retention (binding)

- Validate: `.pdf` extension; MIME; PDF magic-byte signature; reject non-PDF / mismatch / malformed / malicious.  
- Maximum file size: **20 MiB**; maximum pages: **50** (design defaults).  
- Sanitize stored filename; use generated storage key.  
- Private storage only; authorized or signed access only; **no public bucket**.  
- Deletion: remote provider delete/expire + audit; app retention duration remains **legal OPEN** (ASM-014) but security behavior above is binding regardless.  
- Logs: never PDF body, extracted business content dumps, or credentials. Gate errors list stable field targets only.

### 25. Maps behavior (binding)

**PACK-006 may:** generate a static external Google Maps link from reviewed stops; store human-supplied or document-extracted kilometer values under the same review/confirm rules.

**PACK-006 must not:** call a Maps routing/Directions API; calculate or optimize route distance.

**PACK-007 retains:** route calculation; alternatives; route optimization; corridor comparison; Maps/direct-route comparison.

### 26. Save behavior (binding)

- **Explicit Save** for reviewed edits (no autosave in this ADR).  
- Unsaved-changes warning before navigation.  
- Confirmation operates only on **persisted** values.  
- Reorder is saved explicitly (with `expected_version`).  
- Successful save increments aggregate version once.  
- Stale save → `ORDER_VERSION_CONFLICT`.

## Alternatives considered

| Option | Why not |
|---|---|
| Order-level “confirm all” only | Insufficient; mandatory field-level states |
| Auto-confirm high confidence | Violates “suggestions only” |
| New Auth role `dispatcher` | Forbidden without separate ADR; use manager |
| Client-only Weiter gate | Bypass risk; server 409 required |
| Color-only status | Inaccessible; not SoT |
| Index-based `stops[i]` identity | Breaks on reorder; use `stop_id` |
| Autosave without CAS | Lost updates / ambiguous conflicts |

## Consequences

- C1/C2/H1–H4 closed; Architect Re-Review **PASS**.  
- Apply must implement aggregate CAS, idempotency, stable stop IDs, partial loads/legs, full audit catalog, server gate, explicit Save.

- **DS-005 OPEN**: blocks live Gemini/xAI and real-customer PDF processing.  
- Non-provider Builder Dry-Run authorized after acceptance; **Builder Apply still requires separate human authorization**.  
- Private samples gitignored. Never commit sample binaries/manifests or operational values into tracked docs.
