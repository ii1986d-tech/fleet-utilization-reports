# ADR-001 — Application stack

> Generated by Project Launcher Pro v4.4.1 on 7/29/2026

## Context

Greenfield FUR-001 needs a small internal reporting stack. Anweisungen prefer Next.js App Router, TypeScript strict, Supabase/PostgreSQL, n8n, server-side exports. No existing application conventions in the repo.

## Alternatives

### A — Next.js App Router + TS strict + Supabase + n8n — 88/100

Matches Anweisungen; Auth/RLS/Postgres co-located; n8n for schedules without custom cron service.

- Cost: 2/5
- Speed: 4/5
- Maintainability: 4/5
- Scalability: 3/5
- Risk: 2/5
- Lock-in: 3/5

### B — Separate Nest/Express API + React SPA + managed Postgres + OS cron — 62/100

More moving parts for a small internal tool; duplicates Auth/ORM work.

- Cost: 3/5
- Speed: 2/5
- Maintainability: 3/5
- Scalability: 4/5
- Risk: 3/5
- Lock-in: 2/5

### C — Low-code only (n8n UI + sheets) — 35/100

Fails historical assignment audit, RLS roles, PDF/Excel quality gates, and testability requirements.

- Cost: 2/5
- Speed: 3/5
- Maintainability: 1/5
- Scalability: 1/5
- Risk: 5/5
- Lock-in: 4/5

## Decision

Next.js App Router + TypeScript strict + Supabase + n8n

## Rationale

Highest fit to stated constraints; smallest operable surface for MVP; existing project conventions absent so preference stack applies.
