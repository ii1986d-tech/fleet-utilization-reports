# ADR-004 — Frotcom integration strategy for early packs

> Generated by Project Launcher Pro v4.4.1 on 7/29/2026

## Context

Frotcom contract (auth, endpoints, fields, rate limits) is **not verified**. Anweisungen forbid inventing endpoints and require an isolated adapter with mocks until verified.

## Alternatives

### A — Adapter interfaces + mock fixtures; real calls only after verified contract — 92/100

Unblocks Phases 1–4; keeps Phase 5 gated on DS-001.

- Cost: 2/5
- Speed: 4/5
- Maintainability: 5/5
- Scalability: 3/5
- Risk: 1/5
- Lock-in: 2/5

### B — Implement guessed REST paths from public marketing docs — 15/100

High chance of wrong contract; false production confidence.

- Cost: 2/5
- Speed: 3/5
- Maintainability: 1/5
- Scalability: 2/5
- Risk: 5/5
- Lock-in: 4/5

### C — Block all application work until live Frotcom access exists — 50/100

Safe for integration but stalls foundation, assignments, and UI value delivery.

- Cost: 1/5
- Speed: 1/5
- Maintainability: 3/5
- Scalability: 3/5
- Risk: 2/5
- Lock-in: 1/5

## Decision

Isolated `src/lib/frotcom/` adapter (interfaces, schemas, mocks). No live production integration until Decision Stop DS-001 is resolved.

## Rationale

Matches Anweisungen §9; maximizes progress without fabricating API facts.
