# ADR-007 — Excel assignment import policy

> Architect decision 2026-07-30 · PACK-003
> Updated 2026-07-30 after Builder dry-run corrections

## Context

Anweisungen §7.2 / Phase 3 require controlled Excel import of time-dependent `vehicle_assignments` with preview, conflicts, confirmation, protocol, and downloadable error report. PACK-002 enforces ADR-005 (overlap) and ADR-006 (no hard delete). Import must not weaken those rules.

Builder dry-run (`READY_WITH_REQUIRED_CORRECTIONS`) required explicit locks on dependency, limits, worksheet rule, migration, state machine, preview persistence, CAS confirm, per-row TX, idempotency, plate normalization, create-on-confirm default, dates, formulas, file validation, and error contracts.

## Decisions

### D1 — Scope

Imports **assignment rows only**. No daily reports, Frotcom, settings, or report exports.

### D2 — Dependency: `exceljs` (approved for Apply)

| Rule | Binding |
|---|---|
| Package | **`exceljs`** |
| Purpose | Server-side `.xlsx` parse + error-report workbook generation |
| Client | **No** workbook parsing in the browser for authoritative validation |
| Install timing | **Builder Apply only** (not Architect/docs); lockfile pins version |
| Macros | Never executed |
| Formats | `.xlsx` only — reject `.xls`, `.xlsm`, `.xlsb`, CSV, ODS |

### D3 — File limits (ASM-011 **RESOLVED** for PACK-003)

| Limit | Value |
|---|---:|
| Max upload size | **5 MiB** |
| Max data rows | **2000** |
| Worksheets | **Exactly one** non-empty worksheet (see D4) |
| Blank trailing rows | Ignored (not counted toward 2000 once trailing) |
| Over limit | **Blocking file-level error** |

### D4 — Worksheet selection

1. Identify worksheets with at least one non-empty cell in the used range.
2. If **zero** non-empty sheets → file error.
3. If **more than one** non-empty sheet → **reject** (do not merge, do not pick silently).
4. If **exactly one** → use that sheet; record `worksheet_name`.

(Supersedes earlier “Assignments-or-first” soft rule.)

### D5 — Partial success (binding)

Invalid/conflict rows must not abort persistence of other valid rows. Job summary reflects actual per-row outcomes.

### D6 — No silent overwrite

- DB / in-file overlap → row CONFLICT; not persisted (`ASSIGNMENT_OVERLAP` semantics).
- Exact duplicate assignment → **SKIP** (idempotent); increment `skipped_rows`.
- No Option B close+create inside import.

### D7 — Master resolution

| Master | Behavior |
|---|---|
| Vehicle | Match via **normalized plate** (D11) against `registration_number` (also normalize stored candidates for compare). **Never auto-create.** Unknown or inactive → blocking ERROR |
| Driver / Customer | Match active name (trim, NFKC, case-insensitive). Inactive-only → ERROR. Unknown → ERROR unless admin enabled create-on-confirm |
| Create-on-confirm | **Default OFF**. Explicit admin enable before confirm. Create only during confirm, server-side, normalized names, duplicate-safe; record on `import_job_rows`. **Never create vehicles** |
| Party rule | ≥1 of driver/customer after resolution |

### D8 — Source stamp

`source = 'excel_import'`; `created_by` = confirming admin when available.

### D9 — Authorization

Admin-only: upload, parse, preview, confirm, download error report, list jobs.
Keep / extend RLS: `import_jobs` + `import_job_rows` **admin-only**. No authenticated-write widening. Manager/viewer: deny import mutations (MVP: deny job reads too).

### D10 — File validation

Require **all** of:

- Extension `.xlsx` (case-insensitive)
- Valid OOXML/ZIP signature + successful `exceljs` open
- Not encrypted / not password-protected
- Within size/row limits
- Exactly one non-empty worksheet

Reject renamed unsupported formats, malformed archives, and required fields that cannot be resolved safely (including external-link-dependent values).

**Do not rely on browser MIME alone.**

### D11 — License-plate normalization (canonical)

For lookup and duplicate keys:

1. Trim leading/trailing whitespace
2. Unicode NFKC
3. Uppercase
4. Remove spaces and hyphens
5. Keep letters and digits (other punctuation stripped)
6. Compare on normalized value; retain original display separately in payload

Empty after normalize → ERROR.

### D12 — Date handling (date-only, no TZ shift)

Accepted:

- Native Excel date cells (calendar date parts in UTC extraction — no local TZ day shift)
- Excel serial dates
- `YYYY-MM-DD`
- `DD.MM.YYYY`
- `DD/MM/YYYY` **only when unambiguous** (day > 12 or month unambiguous)

Reject ambiguous strings. Empty `valid_until` → open-ended NULL. `valid_until < valid_from` → blocking ERROR.

### D13 — Formula handling

- Application **never executes** formulas
- Required fields: formula cells **rejected** (including when only a cached result exists — **do not trust cache** for required fields)
- Optional remark: may import literal displayed text **only if** safely available without trusting formula evaluation; otherwise warn and leave empty

### D14 — Server-stored preview (mandatory)

At validate time, persist normalized rows into `import_job_rows`.
Confirm accepts **`jobId` + options only** (e.g. `createNewMasters`).
**Client-supplied preview rows are never trusted** on confirm.

### D15 — State machine

Allowed statuses:

`uploaded` → `parsed` → `validated` → `confirming` → `completed` | `completed_with_errors`
Any stage may → `failed`
**Forbidden:** any transition from `completed` / `completed_with_errors` back to `confirming` / `validated`.

| Transition | Meaning |
|---|---|
| → `uploaded` | Job row created (metadata) |
| → `parsed` | Workbook opened; sheet selected |
| → `validated` | Rows written; preview ready |
| → `confirming` | **CAS** from `validated` only |
| → `completed` | All confirmable rows persisted or idempotently skipped |
| → `completed_with_errors` | ≥1 row failed persistence / remained ERROR after confirm attempt |
| → `failed` | Job-level failure preventing row processing |

### D16 — Confirmation CAS

Atomic: `UPDATE import_jobs SET status='confirming', confirmation_started_at=now(), … WHERE id=? AND status='validated'`.
If 0 rows updated → **HTTP 409** `IMPORT_ALREADY_CONFIRMED` (covers already confirming/completed).
No duplicate confirmation.

### D17 — Transaction granularity

**Per-row** isolated persistence (own transaction or equivalent). One failing row must not roll back successful rows. After all rows: set terminal status; counters from stored row states.

### D18 — Idempotency

**File-level:** `source_sha256` + import configuration version (documented constant in Apply). New upload may create a **new** job; does not by itself insert duplicates.

**Row-level exact duplicate key:** normalized vehicle plate + normalized driver name/id + normalized customer name/id + `valid_from` + `valid_until` + normalized remark.
Match existing assignment → SKIP; `skipped_rows++`; no new assignment.

### D19 — Error contracts (`AppError`)

Shape: `{ code, message, httpStatus, details? }`.

| HTTP | Code (examples) |
|---:|---|
| 400 | `VALIDATION_ERROR` / `IMPORT_FILE_INVALID` |
| 401 | `UNAUTHENTICATED` |
| 403 | `FORBIDDEN` |
| 404 | `NOT_FOUND` |
| 409 | `ASSIGNMENT_OVERLAP` (single-assignment APIs / row mapping) |
| 409 | `IMPORT_ALREADY_CONFIRMED` |
| 413 | `IMPORT_FILE_TOO_LARGE` |
| 422 | `IMPORT_VALIDATION_FAILED` (file/row validation blocking confirm start when no valid path — also used when returning structured validation failure for file-level reject after parse) |
| 500 | `INTERNAL_ERROR` |

Preview of a validatable file returns **200** with job + row statuses (row errors live in `import_job_rows`). Confirm returns **200** + summary for partial success; **409** only for CAS / already confirmed (not for individual row overlaps inside a multi-row confirm).

### D20 — Summary invariants

Derive counters from `import_job_rows`, never from the client.

After validate:

`total_rows = valid_rows + invalid_rows`
(where `valid_rows` = rows eligible to attempt persist if create-options satisfied; `invalid_rows` = ERROR/CONFLICT at validation)

After confirmation:

`valid_rows = persisted_rows + skipped_rows + failed_rows`
(recalculate or maintain transactionally from row `persistence_status`)
