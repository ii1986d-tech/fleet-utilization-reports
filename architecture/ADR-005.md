# ADR-005 — Vehicle assignment overlap policy

> Architect decision 2026-07-30 · PACK-002
> Updated 2026-07-30 after Builder dry-run corrections

## Context

Anweisungen §8.4 requires detecting overlapping active assignments for the same dimension. Without a hard rule, historical attribution (driver/customer on a report day) becomes ambiguous and TM-10 fails. Application-only checks cannot stop concurrent admin writes.

## Alternatives

### A — Hard block per `vehicle_id` + mandatory DB exclusion — 95/100

Inclusive ranges; adjacent days OK; DB enforces under concurrency.

### B — Soft warn only in UI — 40/100

### C — Separate driver vs customer tracks — 55/100 (schema redesign)

## Decision

**Hard block overlapping `vehicle_assignments` for the same `vehicle_id`.**

### Overlap predicate (app + docs)

Two rows overlap iff they share `vehicle_id` and:

`valid_from_a <= coalesce(valid_until_b, +∞)` AND `valid_from_b <= coalesce(valid_until_a, +∞)`

- Adjacent: end on `D`, start on `D+1` → **allowed**
- Identical or intersecting ranges (including same-day shared endpoint) → **rejected**
- Open-ended (`valid_until IS NULL`) blocks any later/earlier range that intersects the unbounded side

### Mandatory database enforcement (PostgreSQL / Supabase)

**Mechanism:** GiST **exclusion constraint** (preferred, race-safe):

```sql
-- Conceptual; actual migration file created only at Apply (not in this Architect step)
CREATE EXTENSION IF NOT EXISTS btree_gist;

ALTER TABLE public.vehicle_assignments
  ADD CONSTRAINT vehicle_assignments_vehicle_period_excl
  EXCLUDE USING gist (
    vehicle_id WITH =,
    daterange(
      valid_from,
      COALESCE(valid_until, 'infinity'::date),
      '[]'
    ) WITH &&
  );
```

- `'[]'` = inclusive bounds (matches ADR predicate)
- `infinity` for open-ended periods
- Concurrent overlapping inserts/updates: one succeeds, one fails at commit
- **Application validation remains mandatory** for UX; DB is the final integrity boundary

**Fallback** (only if exclusion cannot be enabled on the target plan): `BEFORE INSERT OR UPDATE` trigger raising `P0001` / mapped to overlap — still mandatory, not optional.

### API conflict

- HTTP **409**
- `code`: **`ASSIGNMENT_OVERLAP`**
- Include conflicting id(s) and ranges when safe; never secrets

### Forward migration / rollback

| Direction | Behavior |
|---|---|
| Forward | Additive migration: `btree_gist` (if needed) + exclusion constraint; fails if overlapping rows exist — resolve data first |
| Rollback | Forward-fix migration: `DROP CONSTRAINT vehicle_assignments_vehicle_period_excl` only — **do not** drop tables |
| Apply timing | At PACK-002 Apply via approved remote (`db push`) or local when available — **not** in Architect correction step |

## Consequences

- PACK-003 Excel import must reuse the same helpers and will hit the same DB guard
- Tests must prove DB rejects overlap even if app validation is bypassed

## Status

**ACCEPTED** (mandatory DB guard after dry-run correction).
