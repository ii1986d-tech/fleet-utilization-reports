# Data Model Gate — FUR-001

> Generated by Project Launcher Pro v4.4.1 on 7/29/2026

## Sources

- Frotcom API payloads (source) — unverified contract → mock until DS-001
- Manual / Excel assignment imports (plan + actual assignment)
- Calculated utilization status and standing time (calculated)
- Stored daily reports (actual SoR in Supabase)

## Required separation

| Category | Meaning | Examples |
|---|---|---|
| Source | immutable or externally observed input | Frotcom raw payload reference |
| Plan | intended future / assigned state | vehicle_assignments |
| Actual | verified outcome | vehicle_daily_reports metrics |
| Calculated | derived value | utilization_status, standing_seconds |

## Entities and fields

Greenfield — no existing tables. Proposed schema from Anweisungen §8:

### vehicles

`id`, `external_frotcom_id`, `registration_number`, `display_name`, `vehicle_type`, `active`, `metadata`, `created_at`, `updated_at`

### drivers

`id`, `external_frotcom_id` nullable, `full_name`, `employee_number` nullable, `active`, `created_at`, `updated_at`

### customers

`id`, `name`, `external_reference` nullable, `active`, `created_at`, `updated_at`

### vehicle_assignments

`id`, `vehicle_id`, `driver_id` nullable, `customer_id` nullable, `valid_from`, `valid_until` nullable, `source` ∈ {manual, excel_import, system}, `notes` nullable, `created_by`, `created_at`, `updated_at`

Rules: `valid_until >= valid_from` when set; detect overlapping active assignments per dimension; auditability required.

### vehicle_daily_reports

`id`, `report_date`, `vehicle_id`, `actual_driver_id` nullable, `assigned_driver_id` nullable, `customer_id` nullable, `start_time`/`end_time` nullable, location text + lat/lon nullable, `distance_km`, `driving_seconds`, `driver_driving_seconds` nullable, `standing_seconds`, `idle_seconds` nullable, `operation_window_seconds`, `utilization_status`, `source_type`, `source_reference` nullable, `data_quality_status`, `sync_status`, `synchronized_at`, `raw_payload_reference` nullable, timestamps

Uniqueness: `(vehicle_id, report_date)` — idempotent upsert.

`data_quality_status` ∈ {complete, partial, missing, suspicious, manually_corrected}

### import_jobs

`id`, `file_name`, `status`, row counters, `error_report_reference`, `created_by`, `created_at`, `completed_at`

### sync_runs

`id`, `source`, `report_date`, timing, `status`, record counters, `error_summary`, `retry_count`

### utilization_settings

`minimum_target_driving_seconds` (default 9h), `warning_target_driving_seconds` (default 7h), `business_timezone`, `report_generation_time`, `updated_by`, `updated_at`

## Indexes / integrity (Phase 1)

- FKs on all `*_id` references
- Unique `(vehicle_id, report_date)`
- Partial indexes for active vehicles/assignments
- RLS policies per role

## Ownership, retention and privacy

Internal fleet ops data. Retention policy [OFFEN — ASM-005]. No public exposure. Secrets never in tables as plaintext credentials for Frotcom (use env/n8n credentials).
